# 访存隔离方案交接文档

# 先前存在问题
在实验课工程中，PS侧的ARM与PL侧的学生逻辑共享一个访存通路，出现了概率性系统死机的问题。  
原因怀疑是当某个学生逻辑访存事务出现差错时，DDR MIG（控制器）带宽会被学生逻辑占用，进而影响到ARM的访存，导致访存失败。



# 解决方式
PS和PL之间双向数据搬移通过DMA进行隔离

## 硬件设计
为了方便多个数据搬移任务并行处理，设计中选择支持多通道搬移数据的 AMD Multichannel DMA（MCDMA）作为 DMA 引擎的核心。  
MCDMA 进行数据传输的流程大致如下：

1. 需要通过设置通道控制寄存器启用 MM2S 通道。
2. 为 MM2S 通道配置一个或多个描述符（BDs），这些描述符包含了写操作的  
详细信息，如数据源地址、目的内存地址、传输大小等。
3. 通过编程 Tail Descriptor（TD）寄存器来指向描述符链的尾部。这会触发硬件  
开始从该链表获取和处理描述符。
4. 通过设置 MCDMA 的 RunStop 位来启动数据传输。此时，MCDMA 硬件开始  
按照描述符链中的指令执行写操作。
5. MM2S 通道从 AXI4-MM 接口接收数据。通过 AXI4 Stream 接口进行数据传  
输。
6. 每个传输描述符的状态字段会被 MCDMA 硬件更新，以反映传输的状态，如  
是否完成、是否有错误发生等。
7. 如果在传输过程中检测到错误，如地址解码错误或从设备错误，MCDMA 将  
停止传输并设置状态寄存器中的错误位。软件需要检查这些错误位并进行相  
应的错误恢复处理。

由于 MCDMA 通过 AXI4 Stream 接口输出数据，而 AXI4 Stream 为非存储映射接口，其数据传输时不需要地址。因此，为了将数据搬移到目的地址，需要将地址信息通过 MCDMA 其他行为显示出来。

设计中为 MCDMA 配备了模块 DMA_Writer，模块设计的目的是使 MCDMA 能够支持 AXI4-MM 接口到AXI4-MM 接口的数据搬移，让 DMA 引擎能够在 PS 端内存和 PL 端内存中间搬移数据，进而对 PS 与 PL 之间内存访问进行隔离。

![1724347933538-5f28f747-dd22-4f0b-a47e-2c53b908f14a.png](./img/yHnZFdEqGM9ft2jf/1724347933538-5f28f747-dd22-4f0b-a47e-2c53b908f14a-831530.png)

<font style="color:rgb(0,0,0);">如上图所示，DMA_Writer包含三个主要模块：AXIS_CNTL_parser 模块、Mover_CMD_generator 模块以及 Datamover_Firewall 模块。</font>

<font style="color:rgb(0,0,0);">由于 MCDMA 进行数据搬移前会在 M_AXI_CNTRL 接口上显示用户应用域信息，所以可以通过修改 MCDMA 设备驱动的方式把搬移数据的目的地址信息 存放在用户应用域 APP0 和 APP1 中。为了将数据搬移到目的地址， DMA Writer 通过 AXIS_CNTL_parser 模块解析 M_AXI_CNTRL 接口的行为获得目 的地址，再将目的地址和 MCDMA 目的传输通道号交给 Mover_CMD_generator 模 块生成 Data mover 搬移命令，交给 MCDMA 通道对应的 Data mover 进行数据搬移操作，最终通过 AXI Interconnect 将信号整合，生成 AXI4 Memory Mapped 写事务， 最终将数据搬移到目的地址。 </font>

### <font style="color:rgb(0,0,0);">AXIS_CNTL_parser 模块</font>
<font style="color:rgb(0,0,0);">为了使 MCDMA 能够支持 AXI4-MM 接口到 AXI4-MM 接口的数据搬移，需要将搬移的目标地址信息通过其他途径交给整个 DMA 引擎的 AXI4-MM 输出接 口。为了完成上述目标，AXIS_CNTL_parser 模块负责地址解析功能实现。 根据下图所示，MCDMA 接收到 Start of Frame（SOF）控制信息后，会读取第一个 BD 中填写的用户应用域信息 APP0-APP4，并把这些值通过 MCDMA 的</font><font style="color:rgb(0,0,0);">M_AXI_CNTRL 接口表现出来。根据 MCDMA 的这个行为，我们可以在软件驱 动中将数据搬移的目的地址填入用户应用域信息中。通过 AXIS_CNTL_parser 模块 读取M_AXI_CNTRL 接口的行为。当读取到M_AXI_CNTRL 接口的值为AXI_DMA_append_flag 时，就将M_AXI_CNTRL 接口后两个始终周期的值读出并传递给Mover_CMD_generator 模块，用以生成目的地址信息。</font>

![1724348220460-de4ac4bb-2df7-498e-9205-e8adf707b686.png](./img/yHnZFdEqGM9ft2jf/1724348220460-de4ac4bb-2df7-498e-9205-e8adf707b686-106769.png)

### <font style="color:rgb(0,0,0);">Mover_CMD_generator 模块</font>
<font style="color:rgb(0,0,0);">在数据传输过程中，AXI Stream 的 Burst 最大长度不受限，且可以设为任意长 度。而 AXI-MM 的 burst 最大为 256 个 beats，宽度 SIZE 则必须是 2 的整数次方。 因此需要对 Stream 端的数据进行切分，当 AXI-MM 的 Burst 长度设为 256 时，应该 在 AXIS_MM2S 数据口每计数 256 次后在 AXI-MM 插入一个 last 信号。此外，对 于不定长的 Stream 数据，并不一定是 256 的整数倍，最后一段数据长度可能是一 个任意值（即计数不到 256 时，AXIS_MM2S 的 tlast 已经传入），此时 AXI-MM 将 会出现一个不完整的 Burst 动作，且这一情况从 DMA_Writer 的角度无法预知。由 于 AMBA 标准强制要求 Burst 必须正常完成不能中止，因此可以在 tlast 之后填充 0 数据，并拉低 wstrb 将相应的补 0 数据段标识为无效数。而对于 wlast 信号，则当 Beats 计数为满一次 Burst 长度时，或遇到 tlast 信号到来时，输出有效；当最后一 段数据长度不够一次完整 Burst 动作时，应该等待填充 0 数据之后，延迟输出 tlast 高有效信号。 为了方便硬件结构的设计，设计中选择使用 Data Mover 实现对 AXI-MM 的 Burst 的自动切分。利用 Data Mover 能够自动进行 4KB 地址边界保护这一功能，将 MCDMA 输出端的 AXI4 Stream 数据流交给 Data Mover 处理，最后从 AXI4-MM</font>接口进行数据搬移。  
Data Mover 执行写操作的过程如下：

1. <font style="color:rgb(0,0,0);">Data Mover 通过其 AXI4-Stream 命令接口接收到一个传输命令。这个命令包  
</font><font style="color:rgb(0,0,0);">含了传输所需的关键信息，如目标地址、要传输的数据量等。s_axis_cmd_tready  
</font><font style="color:rgb(0,0,0);">表示 Data Mover 已经准备好接受传输命令，s_axis_cmd_tvalid 表示传输命令  
</font><font style="color:rgb(0,0,0);">有效。</font>
2. <font style="color:rgb(0,0,0);">根据命令，Data Mover 在AXI4 接口上发起写事务的地址请求，通过m_axi_s2mm_awvalid  
</font><font style="color:rgb(0,0,0);">信号表明地址请求有效。</font>
3. <font style="color:rgb(0,0,0);">Data Mover 通过AXI4-Stream接口接收要写入的数据，并通过s_axis_s2mm_tready  
</font><font style="color:rgb(0,0,0);">信号表明它已准备好接收数据，通过 s_axis_s2mm_tvalid 信号表明接收到的  
</font><font style="color:rgb(0,0,0);">数据的有效。</font>
4. <font style="color:rgb(0,0,0);">接收到的数据被Data Mover 发送到AXI4 写数据通道上，通过m_axi_s2mm_wvalid  
</font><font style="color:rgb(0,0,0);">信号表示传输数据有效。</font>

<font style="color:rgb(0,0,0);">为了让 Data Mover 知道数据搬移的目的地址，需要向 Data Mover 发送一个包含目的地址、数据传输长度、传输方向、传输类型等信息的指令，因此设计了Mover_CMD_generator 模块进行 Data Mover 指令的生成。Mover_CMD_generator模块将 AXIS_CNTL_parser 模块获取的两个 32 位用户应用域信息 APP0、APP1 整合在一起，得到 40 位的地址信息，再将地址信息与数据传输长度、传输方向、传输类型等信息整合位完整的命令信息，交给下一个模块进行处理。</font>

### <font style="color:rgb(0,0,0);">Datamover_Firewall 模块</font>
<font style="color:rgb(0,0,0);">由于 Data Mover 具有利用缓冲去储存没有来得及处理的数据的能力，如果在 传输命令到来之前传输的数据已经有效，则会导致 Data Mover 缓冲区保存有不 应该被传输的数据。所以需要按照规定时序，确保Data Mover 接收到的命令的 时刻早于有效数据到达 Data Mover 的时刻。也就是说，需要在 s_axis_cmd_tready 和 s_axis_cmd_tvalid 信号为高电平之后才能允许 s_axis_s2mm_tvalid 信号变为高电 平。 基于以上描述的原因，设计中在 DMA Writer 中添加了 Datamover_Firewall 模块， 模块确保在 Data Mover 收到传输命令之前传输数据一直处于无效状态；当传输命 令到来之后，传输数据才能具备有效性。 同时，为了保障 MCDMA 数据传输的多通道并行性，DMA_Writer 使用了多个 Data Mover。每一个 Data Mover 处理一个 MCDMA 通道传输的数据。为了实现上 述功能，Datamover_Firewall 模块读取代表 MCDMA 传输数据通道的 s_axis_tdest 信号，并根据信号所反映的数据通道来源，将通道所对应的 Data Mover 接收到的 数据进行有效性处理，而对其他通道对应的 Data Mover 接收到的数据进行无效性处理。 </font>

<font style="color:rgb(0,0,0);">通过上述的设计DMA Writer既能解决MCDMA 的原生接口难以将一个MemoryMap 的数据直接搬移到另一个 Memory-Map 的位置这一问题，又能发挥 MCDMA 并发传输信息的优势。</font>

## <font style="color:rgb(0,0,0);">SPDK软件驱动</font>
<font style="color:rgb(0,0,0);">为了让 MCDMA 硬件设备能够根据程序的需求运行，需要编写一个 MCDMA 的驱动程序。 </font>

<font style="color:rgb(0,0,0);">在驱动程序中，为了让 MCDMA 能够获取到需要执行的操作，需要一个驻留 在内存中，并且保存有要执行的 MCDMA 操作列表的数据结构。这些指令被组织 成描述符链（BD Chain）。每个描述符都指向下一个要处理的描述符的指针。链中的最后一个描述符然后指向链中的第一个描述符。为了在描述符链中划分数据包，使用帧开始位（TXSOF）和帧结束位（TXEOF）标记数据包的起点与终点。当 MCDMA 获取一个设置了 TXSOF 位的描述符时，就会触发数据包的开始。数据包 继续获取后续的描述符，直到获取到一个设置了 TXEOF 位的描述符。 </font>

<font style="color:rgb(0,0,0);">每一个描述符除了具有指向下一个要处理的描述符的指针，还包含一段数据 缓冲区的地址，MCDMA 将从这个地址中获取要传输的数据。控制字段包含了传输的关键参数，如传输大小、SOF（Start of Frame）和 EOF（End of Frame）标志等。 状态字段，由 MCDMA 在传输完成后更新，包含传输状态信息，如是否完成、是 否有错误等。APP0–APP4 是用户应用域，可以用于存储与当前传输相关的用户定 义数据。根据4.3.1.1节所设计的 AXIS_CNTL_parser 模块，用户应用域中的 APP0 和 APP1 字段应该分别存储传输目的地址信息的高 8 位和低 32 位。</font>

<font style="color:rgb(0,0,0);">为了让 MCDMA 能获取到描述符链并开始数据传输，需要对 MCDMA 的寄存 器进行配置工作。在 MCDMA 开始工作之前，需要在当前描述符（Current Descriptor， CD）寄存器中需要填入描述符链中第一个描述符的地址信息。MCDMA.RS 位是控制 MCDMA 核心运行状态的寄存器位。编程此位为 1 将启动 MCDMA。对于多通道系统，确保数据传输的顺序和优先级非常重要。队列调度寄存器用于配置数据传 输的优先级和调度策略，如严格优先级、加权轮询等。尾部描述符（Tail Descriptor， TD）寄存器指向描述符链的尾部，用于控制描述符链的结束。编程 TD 寄存器会 触发 MCDMA 开始获取和处理描述符链。 </font>

<font style="color:rgb(0,0,0);">为了提升 MCDMA 数据传输能力，本设计基于 SPDK 实现了用户态 MCDMA 驱动。 SPDK 通过将所有必要的驱动全部移到用户态。使得驱动直接与硬件交互而无 需经过内核空间，减少了上下文切换的开销。为了将 MCDMA 和驱动程序进行绑 定，在使用 SPDK 之前，需要从本机内核驱动程序中取消绑定 MCDMA，并绑定 vfio-pci 作为用户态驱动，使得用户程序可以直接访问 MCDMA 的配置空间。 每当用户想要通过 MCDMA 进行数据搬移时，程序会调用 spdk_zmalloc 函数 进行内存分配，这个函数最终会在大页上分配一定范围的地址供应用使用。如下图所示，驱动将要传输的数据存储在大页中，并用描述符记录这些数据的物理地址。 由于这些地址能够被 MCDMA 访问，因此 MCDMA 可以根据描述符链所描述的操作，获取待传输的数据。 </font>
